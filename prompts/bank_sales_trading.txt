# [SPIDER2 BANK & SALES DOMAIN RULES] - STRICT OVERRIDE

1. THE "PURCHASE = WITHDRAWAL" RULE:
In `customer_transactions`, 'purchase' MUST be subtracted from the balance exactly like 'withdrawal'.
- Formula: `SUM(CASE WHEN txn_type = 'deposit' THEN txn_amount WHEN txn_type IN ('withdrawal', 'purchase') THEN -txn_amount ELSE 0 END)`

2. DATE NORMALIZATION (CRITICAL): 
- `bitcoin_transactions.txn_date` and `bitcoin_prices.market_date` are `DD-MM-YYYY`. MUST convert using `SUBSTR` to `YYYY-MM-DD` before joining. 
- `customer_transactions.txn_date`, `veg_txn_df.txn_date`, `veg_whsle_df.whsle_date` are ALREADY `YYYY-MM-DD`. NEVER use `DATE()` or `STRFTIME()` on them in JOIN conditions. Join them directly.

3. RETAIL LOSS MATH (VEGETABLES):
Keep it strictly simple. Do NOT use complex division.
- Total Wholesale Price = `SUM(qty_sold * wholesale_price)`
- Total Loss = `SUM(qty_sold * unit_selling_price * (loss_rate / 100.0))`

4. SHOPPING CART METRICS:
- If asked to group by "each product", you MUST SELECT and GROUP BY `product_id`, NOT `page_name`.
- Abandoned in cart = `SUM(added_to_cart) - SUM(purchases)`.

5. PERCENTAGE DENOMINATOR:
If computing "percentage of customers", the denominator MUST be the total unique customers in the raw table: `(SELECT COUNT(DISTINCT customer_id) FROM customer_transactions)`.

6. MONTH-END BALANCE VS CUMULATIVE:
- If a prompt asks for operations that occurred "during that specific month", calculate the NET CHANGE for that month only. DO NOT make it a cumulative running sum.
- Only use `SUM() OVER (ORDER BY month)` if explicitly asked to "cumulatively sum" or find a "running balance".
